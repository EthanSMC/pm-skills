## 1. 背景与动机

AI 已经让"写文档"这个动作变得廉价，但产品文档生产的真正瓶颈随之转移到了三个地方：

1. **输入质量** — 知识收集不全、不新、不可信，下游再流畅也是空中楼阁；
2. **判断与验证** — 生成容易，挑出错漏难；金融场景下一条编造的监管引用就是事故；
3. **产物间一致性** — PRD、评审结论、原型之间互相漂移，越改越散。

本项目研究并构建一个**金融科技 PM 的端到端 AI 工作流**：从全网知识收集 → 产品设计 → PRD 撰写 → 评审挑刺 → 原型设计，整条链路打通，并以可度量的方式回答"AI 在每个环节的真实价值"。

### 1.1 与前作 pm-skills 的关系

pm-skills 是本项目的前置实践，它验证了"skill 化的 PM 工作流"可行，也暴露了三个教训：

| pm-skills 的问题 | 本项目的对策 |
|---|---|
| 一半 skill 是软件工程（TDD/分支管理/worktree），偏离 PM 主线 | 工程链整体不带入，原型只到"可点击演示"级 |
| 流程驱动、skill 互相编排，复杂度长在调用关系上 | **以产物为中心**：复杂度锁死在 5 份文档模板里 |
| 通用化，每个环节都抽象 | **垂直锁死金融科技**，领域资产是一等公民 |

可复用的部分：pm-brainstorming 的探索方法、write-prd 的模板骨架、prototyping 的前端设计经验，均以"提炼方法、不搬代码"的方式继承。

## 2. 核心设计主张（区别度所在）

### 2.1 以产物为中心，而非以流程为中心

先定义 **5 份标准产物**，每份有固定模板与质量标准；工具只是生产某份产物的薄薄一层操作。产物规格是稳定契约，工具可替换。流水线上**只有一种数据流动方式：文档传递**——上一阶段产出一份 markdown，下一阶段读它。没有编排器、没有自动触发、没有知识库引擎。

### 2.2 证据链（Evidence Chain）作为全流程脊柱

金融 PM 的文档本来就要经得起审计，本项目把这变成架构约束：

> **下游产物的每个关键论断，必须能引用到上游来源。**

- PRD 中的合规要求 → 引用知识简报中的监管条文
- 知识简报中的条文 → 引用原始网页 / 文件（URL + 抓取日期 + 原文摘录）
- 评审报告中的每条挑刺 → 标注依据（量规条款 / 上游证据 / 逻辑推演）

证据链直接治理金融场景最致命的风险——**监管条文幻觉**：每条引用可被人工抽查，抽查通过率是核心度量之一。

### 2.3 AI 三角色分离：研究员 / 起草员 / 质询者

生成内容的那一遍 AI 不能同时负责审查这些内容——它会系统性地为自己辩护。因此 AI 在流程中以三种互相隔离的角色出现：

| 角色 | 出现阶段 | 行为约束 |
|---|---|---|
| **研究员** | 阶段 1 | 只收集、归类、引用，不下产品结论 |
| **起草员** | 阶段 2 / 3 / 5 | 只基于上游产物生成，超出上游证据的内容必须显式标注为"假设" |
| **质询者** | 阶段 4 | 不读起草过程，只读成品；以合规、风控、技术可行性、用户体验四副面孔对抗性评审 |

### 2.4 领域资产包是一等公民的交付物

本项目真正沉淀的不是工具，而是四样**金融科技领域资产**——哪怕工具全部废弃，它们对任何金融 PM 直接有用：

1. **信源清单**：央行 / 证监会 / 金管局 / 银保监等监管渠道 + 竞品动态源 + 行业报告源，含更新频率与可信度分级
2. **合规检查表**：金融产品设计的合规约束前置清单（KYC、适当性、数据合规、营销合规、资金安全…）
3. **金融 PRD 模板**：含风险揭示、合规依据、资金流图等金融特有章节
4. **四视角评审量规**：合规 / 风控 / 技术 / 体验各自的挑刺清单与严重度定级

每期迭代以"资产更厚了多少"作为验收维度之一。

## 3. 流水线总体设计（5 阶段 + 回流）

```
[1 知识收集] → [2 产品设计] → [3 PRD 撰写] → [4 评审挑刺] → [5 原型设计]
     ↑________________________________↓________________↓
                    回流单（结构化问题回写）
```

| 阶段 | 做什么 | AI 角色 | 标准产物 | 质量标准（度量） |
|---|---|---|---|---|
| **1 知识收集** | 按信源清单全网搜集监管 / 竞品 / 用户 / 技术四类信息，结构化归档 | 研究员 | **领域知识简报** | 引用覆盖率 100%；关键信源漏报率（人工对照抽查） |
| **2 产品设计** | 机会识别 + 方案发散收敛，合规约束前置检查 | 起草员（+苏格拉底式提问） | **产品设计稿**（方案 / 权衡 / 合规风险点） | 每个方案附证据引用与假设标注 |
| **3 PRD 撰写** | 设计稿展开为完整 PRD，人改为主、AI 起草为辅 | 起草员 | **PRD** | 关键论断证据链完整率；模板章节齐备 |
| **4 评审挑刺** | 四视角对抗性评审，产出定级问题清单 | 质询者 | **评审报告 + 回流单** | 有效缺陷发现数；误报率；人工复核认可率 |
| **5 原型设计** | PRD 转可点击界面原型（HTML 页面级，非工程项目），偏金融常见形态：开户流程、交易面板、风险揭示页 | 起草员 | **原型 + 原型说明** | PRD-原型一致性核对清单通过率 |

**回流单机制**：阶段 4 / 5 发现的问题以结构化条目（问题、严重度、影响章节、建议）回写上游产物并留痕，避免线性流水线在真实迭代中被打破。回流是文档操作，不是工具编排。

最终形态预计为 **5 个 skill 对应 5 个阶段 + 1 个极薄入口**（对比 pm-skills 的 15+）。

## 4. 分期路线图（每期回答一个研究问题）

### 第一期（W1–W6）：两头 —— 知识收集 + 评审挑刺

选这两段先做，因为它们 AI 价值最确定（信息密集型 + 模式识别型），且**不依赖中间环节即可独立使用**——第一天就能拿现存 PRD 来挑刺。

- 交付：信源清单 v1、知识简报模板 + 收集流程、四视角评审量规 v1、评审流程
- **研究问题**：AI 收集的监管信息可信度够不够？（引用抽查通过率、漏报率）AI 评审的挑刺有多少是人认可的有效缺陷？（认可率、误报率）
- 验收实验：3 份真实 / 仿真金融 PRD 走评审；1 个金融子领域（如支付或财富管理）走完整知识收集，与人工收集对照

### 第二期（W7–W10）：中间 —— PRD 撰写

- 交付：金融 PRD 模板 v1、PRD 起草流程，串通"简报 → PRD → 评审"半条流水线
- **研究问题**：证据链约束下的 AI 起草，相比自由生成，在评审缺陷数和人工修改量上差多少？
- 验收实验：同一需求两种方式各起草一次，进同一评审流程对比

### 第三期（W11–W14）：补全 —— 产品设计 + 原型，全线贯通

- 交付：合规检查表 v1、设计稿模板、原型生成流程、回流单机制
- **研究问题**：端到端走完一条真实需求，总耗时与产物质量相比传统方式如何？回流机制是否真的被用起来？
- 验收实验：1–2 个真实金融需求全流程走通，全程记录度量

## 5. 度量体系（保住"研究项目"属性）

| 度量 | 定义 | 适用阶段 |
|---|---|---|
| 引用抽查通过率 | 随机抽 N 条引用，原文可验证的比例 | 1, 3 |
| 关键信源漏报率 | 人工基准清单中 AI 未覆盖的比例 | 1 |
| 有效缺陷发现数 / 误报率 | 评审挑刺被人认可 / 否决的数量与比例 | 4 |
| 证据链完整率 | PRD 关键论断中有上游引用或假设标注的比例 | 3 |
| PRD-原型一致性 | 核对清单通过率 | 5 |
| 端到端耗时 | 对照传统方式的总时长 | 全程 |

每期收尾输出一份**实验记录 + 结论**，与领域资产、工具一起构成该期交付。

## 6. 范围边界（防膨胀条款）

明确**不做**：

- 不做知识图谱、向量库、置信度评分等知识引擎（文档归档 + 检索即可起步）
- 不做 skill 间自动编排与触发（人显式调用每个阶段）
- 不做软件工程链（TDD / 执行计划 / 分支管理），原型止于可点击演示
- 不做通用领域适配（只服务金融科技，其他领域是未来选项不是本期范围）

任何新增能力须回答："它生产或改进哪份标准产物？"答不上来即拒绝。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 监管信源抓取受限（付费墙 / 反爬） | 信源清单标注可达性，优先官方公开渠道；不可达的标注为人工补充项 |
| 证据链要求拖慢起草体验 | 仅约束"关键论断"（合规、资金、风控相关），一般描述不强制 |
| 评审量规初版质量不足导致误报多 | 第一期以人工复核校准量规，量规本身按版本迭代 |
| 范围回潮、重蹈 pm-skills 复杂度 | 第 6 节防膨胀条款 + 每期收尾做一次"复杂度审计"（skill 数、调用关系数） |
| 单人项目精力不足 | 每期产物均可独立使用，任何一期停下都有完整交付 |

---

## 8. 成功标准

项目结束时能够：

1. 用这条流水线把 **1–2 个真实金融需求**从知识收集走到可点击原型，全程证据链可抽查；
2. 用数据回答三期各自的研究问题，明确说出"AI 在哪些环节值得长期投入、哪些环节价值有限"；
3. 沉淀出可独立流通的**金融科技 PM 领域资产包**（信源清单、合规检查表、PRD 模板、评审量规）v1。
