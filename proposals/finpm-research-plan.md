# 立项书：金石（FinPM）— 决策驱动的 PRD 形成系统研究项目

> 代号「金石」：金，金融；石，证据。言之有据，金石为证。
>
> 状态：立项规划 v2（决策驱动重构版）｜ 日期：2026-06

---

## 1. 核心理念：AI 管理文档的形成过程，而不是替人写文档

AI 已经让"生成一份像样的 PRD"变得廉价，但生成出来的 PRD 有一个致命问题：**里面的设计决策没有真正被做过**。文档看起来完整，实际上是 AI 的平均化想象，PM 既没有想清楚，也无法为其中任何一条辩护。

本项目反其道而行：

> **PRD 不是"写"出来的，是"问"出来的。**
> AI 的职责是管理文档的形成过程——通过多轮追问把设计决策逼出来、用挑刺对每个决策做压力测试、经审批门确认入档——**所有设计决策由人做出，AI 保证没有决策被遗漏、没有决策未经质疑、没有未批准的内容混入文档。**

最终的 PRD 是全部已批准决策的汇编投影。没有任何一段 PRD 内容是 AI 自由创作的。

### 1.1 与前作 pm-skills 的关系

pm-skills 是前置实践，验证了 skill 化 PM 工作流可行，也留下三个教训，本项目逐条对策：

| pm-skills 的问题 | 本项目的对策 |
|---|---|
| 流程驱动、15+ skill 互相编排，复杂度长在调用关系上 | **决策驱动**：复杂度锁死在"决策清单 + 台账状态机"这两个数据结构里 |
| AI 大量代笔，产物是 AI 的而不是人的 | AI 只问、只挑刺、只记录；**设计决策全部由人做出** |
| 通用化、领域抽象 | 垂直锁死金融科技，金融产品决策清单是核心资产 |

## 2. 系统设计

### 2.1 中心产物：决策台账（Decision Ledger）

整个系统的中心不是 PRD 文档，而是一份**决策台账**。金融产品需要做的每一个设计决策在台账中各占一条记录：

```
决策点：D-07 资金托管方式
状态：已批准                        # 待讨论 / 讨论中 / 已决待审 / 已批准 / 已失效
候选方案：A 银行存管  B 持牌支付机构备付金  C 自有账户（已被合规挑刺否决）
最终选择：A，理由：……
证据引用：知识简报 §2.3（监管条文 X，原文链接+抓取日期）
挑刺记录：质询者质疑 A 的对账时效 → 人维持原选择，补充对账方案
批准：2026-06-xx，批准人确认
```

台账是一份结构化 markdown，人类可读、可直接编辑。**PRD 由"已批准"状态的决策自动汇编生成**；台账走不完，PRD 就不存在 v1——完整性门控由数据结构天然保证，不需要流程纪律。

### 2.2 单个决策的形成循环：追问 → 挑刺 → 审批

每个决策点走同一个固定循环：

```
 ┌─→ ① 追问：AI 带着证据提问，呈现候选方案与权衡（不替人选）
 │   ② 决策：人做出选择，可补充理由
 │   ③ 挑刺：AI 切换对抗立场，从合规/风控/技术/体验四视角质疑这个选择
 └── ④ 人修订（回到①）或坚持（附辩护理由）
     ⑤ 审批：人显式确认 → 决策入档，状态置为"已批准"
```

三条硬规则：

1. **追问必须带证据**——AI 的每个问题和候选方案尽可能引用知识简报中的监管条文 / 竞品事实 / 用户数据，无证据的追问标注为"经验推测"；
2. **挑刺与追问角色隔离**——质询者不参与方案呈现，只攻击已做出的选择，避免 AI 为自己呈现的选项辩护；
3. **审批是人的显式动作**——AI 不得将任何决策自动置为"已批准"。

### 2.3 AI 三角色：研究员 / 主持人 / 书记员

| 角色 | 职责 | 行为约束 |
|---|---|---|
| **研究员** | 全网收集监管 / 竞品 / 用户 / 技术信息，维护知识简报，为追问和挑刺供给证据 | 只收集、归类、引用，不下产品结论 |
| **主持人 + 质询者** | 驱动决策循环：追问、呈现权衡、对抗性挑刺、追踪台账状态 | 不替人决策；挑刺时不读自己的追问记录，只攻击决策结果 |
| **书记员** | 把已批准决策汇编成 PRD，维护台账与 PRD 的一致性 | 只汇编、不创作；发现台账与 PRD 漂移时报告而非擅自修改 |

### 2.4 证据链（Evidence Chain）

金融文档要经得起审计，本项目把这变成架构约束：**台账中每个决策的证据引用一路可追溯到原始来源**（URL + 抓取日期 + 原文摘录）。这同时治理金融场景最致命的风险——监管条文幻觉：每条引用可被人工抽查，抽查通过率是核心度量。

### 2.5 文档生命周期管理

AI 管理"文档本身"还包括时间维度：

- **失效检测**：研究员发现新监管动态 / 竞品变化时，标记受影响的已批准决策为"已失效待重审"，并说明原因——文档不会无声过期；
- **一致性守护**：任何对 PRD 的人工直接修改，书记员核对其是否对应台账中的已批准决策，不对应则提示"先补决策，再改文档"；
- **决策履历**：每个决策的讨论、挑刺、改选过程全程留痕，半年后回看能知道"当初为什么这么定"。

## 3. 全流程：决策循环为核，收口在 PRD

```
[知识收集]──证据──→ [决策循环：追问→挑刺→审批]×N ──汇编──→ [PRD]
  研究员                    主持人+质询者                  书记员
                                 ↑__________失效检测回流__________|
```

| 环节 | 说明 | 产物 |
|---|---|---|
| **知识收集** | 按金融信源清单（央行/证监会/金管局/银保监 + 竞品 + 行业报告）收集，结构化归档 | 领域知识简报 |
| **决策循环** | 按金融产品决策清单逐项走"追问→挑刺→审批"，主持人追踪进度、提示未触及项 | 决策台账 |
| **PRD 汇编** | 已批准决策投影为 PRD 章节，金融模板（风险揭示、合规依据、资金流图） | PRD |

**PRD 即终点**：原型、实施计划等下游环节不在本项目范围内（见第 7 节）。

数据流动只有一种方式：文档传递。没有编排器、没有自动触发、没有知识库引擎。预计最终 **3–4 个 skill + 1 个极薄入口**。

## 4. 领域资产包（一等公民交付物）

工具废弃了这些资产也独立有价值，每期以"资产厚了多少"验收：

1. **金融产品决策清单**（核心资产）：一个金融产品从立项到上线必须做出的全部设计决策点，按域组织——目标用户与适当性管理、合规路径与牌照依赖、账户体系与资金流、风控规则、定价与费率、数据合规与隐私、异常处理与降级、运营与客诉……每个决策点附追问提纲与常见候选方案
2. **信源清单**：监管 / 竞品 / 行业 / 用户四类信源，含更新频率与可信度分级
3. **四视角挑刺量规**：合规 / 风控 / 技术可行性 / 用户体验各自的质疑清单与严重度定级
4. **金融 PRD 汇编模板**：决策域 → PRD 章节的映射规则，含金融特有章节

## 5. 分期路线图（每期回答一个研究问题）

### 第一期（W1–W5）：决策循环 MVP

先把系统心脏做出来：决策清单 v1（先覆盖 2–3 个决策域，如合规路径 + 资金流）+ 台账格式 + "追问→挑刺→审批"循环。

- **研究问题**：决策循环相比"AI 直接生成 PRD"，决策质量是否可感知地更高？（被挑刺后改变选择的比例、人对最终决策的辩护能力、单个决策的平均轮数与耗时）
- 验收实验：拿 1 个真实/仿真金融需求，对 5–8 个决策点完整走循环，与"AI 一次性生成对应章节"对照

### 第二期（W6–W9）：证据供给 + PRD 汇编

接入知识收集为追问供给证据；打通台账 → PRD 自动汇编。

- **研究问题**：带证据的追问 vs 无证据追问，决策修改率和人的信任度差多少？汇编出的 PRD 在外部评审中表现如何？
- 验收实验：同批决策点分别用带证据/无证据追问各走一遍；汇编 PRD 交第三方 PM 盲评

### 第三期（W10–W13）：全线贯通 + 生命周期

补全决策清单到全部决策域；实现失效检测与回流。

- **研究问题**：从知识收集到 PRD 端到端走完一个真实需求，总耗时与质量如何？失效检测在信息变化时是否真的拦住了过期决策？
- 验收实验：1–2 个真实金融需求从知识收集走到 PRD；人为注入一条监管变化，观察失效检测表现

## 6. 度量体系

| 度量 | 定义 | 验证什么 |
|---|---|---|
| 决策覆盖率 | 决策清单中已批准（或显式暂缓）的比例 | 完整性门控有效 |
| 挑刺改选率 | 被挑刺后人改变选择的比例 | 挑刺有效而非走过场（过低=没用，过高=追问质量差） |
| 追问证据率 / 引用抽查通过率 | 带证据追问占比；引用可验证比例 | 证据链可信 |
| 决策辩护测试 | 随机抽决策，PM 能否复述理由与放弃的备选 | 决策真正被人做过 |
| 失效拦截率 | 注入信息变化后被正确标记的决策比例 | 生命周期管理有效 |
| 单决策平均耗时 | 一个决策点从追问到批准的时长 | 流程成本可接受 |

## 7. 范围边界（防膨胀条款）

明确**不做**：

- **不做 PRD 之后的任何环节**——原型、实施计划、工程链（TDD / 分支管理）全部不在范围内，项目收口在 PRD
- 不做知识图谱、向量库、置信度评分等知识引擎（文档归档 + 检索起步）
- 不做 skill 间自动编排（人显式进入每个环节）
- 不做通用领域适配（只服务金融科技）
- **AI 不代写任何决策内容**——这一条既是产品原则也是范围边界

任何新增能力须回答："它服务于决策台账的哪个状态流转？"答不上来即拒绝。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 决策循环太重，PM 嫌烦不愿走完 | 决策点分级：核心决策走全循环，次要决策允许"快速通道"（追问+批准，跳过挑刺）；以单决策耗时度量持续调参 |
| 挑刺流于形式或过度对抗 | 以挑刺改选率校准量规；挑刺必须给出严重度和依据，不允许泛泛质疑 |
| 决策清单不全 = 系统性盲区 | 清单按版本迭代，每次实验后做"漏掉了什么决策"复盘；允许人在循环中动态新增决策点 |
| 监管信源抓取受限 | 信源标注可达性，优先官方公开渠道，不可达项标注为人工补充 |
| 范围回潮、重蹈复杂度覆辙 | 第 7 节防膨胀条款 + 每期收尾复杂度审计（skill 数、状态数、调用关系数） |

## 9. 成功标准

项目结束时能够：

1. 用决策循环把 **1–2 个真实金融需求**从知识收集走到 PRD，台账中每个决策有人做出、经过挑刺、显式批准、证据可抽查；
2. 用数据回答三期研究问题，尤其是核心命题：**"被问出来的 PRD"是否在决策质量上可度量地优于"被生成的 PRD"**；
3. 沉淀可独立流通的**金融产品决策清单 + 四视角挑刺量规 + 信源清单 + PRD 汇编模板** v1。
