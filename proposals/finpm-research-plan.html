SECTION 01

核心理念：AI 管理文档的形成过程，而不是替人写文档

AI 已经让"生成一份像样的 PRD"变得廉价，但生成出来的 PRD 有一个致命问题：里面的设计决策没有真正被做过。文档看起来完整，实际上是 AI 的平均化想象，PM 既没有想清楚，也无法为其中任何一条辩护。本项目反其道而行：

PRD 不是"写"出来的，是"问"出来的。 AI 的职责是管理文档的形成过程——通过多轮追问把设计决策逼出来、用挑刺对每个决策做压力测试、经审批门确认入档。所有设计决策由人做出，AI 保证没有决策被遗漏、没有决策未经质疑、没有未批准的内容混入文档。最终的 PRD 是全部已批准决策的汇编投影，没有任何一段内容是 AI 自由创作的。

pm-skills 是前置实践，验证了 skill 化 PM 工作流可行，也留下三个教训，本项目逐条对策：

SECTION 02

系统设计

2.1中心产物：决策台账（Decision Ledger）

整个系统的中心不是 PRD 文档，而是一份决策台账。金融产品需要做的每一个设计决策在台账中各占一条记录：

决策点：D-07 资金托管方式
状态：已批准                       # 待讨论 / 讨论中 / 已决待审 / 已批准 / 已失效
候选方案：A 银行存管  B 持牌支付机构备付金  C 自有账户（已被合规挑刺否决）
最终选择：A，理由：……
证据引用：知识简报 §2.3 （监管条文 X，原文链接 + 抓取日期）
挑刺记录：质询者质疑 A 的对账时效 → 人维持原选择，补充对账方案
批准：2026-06-xx，批准人确认

台账是一份结构化 markdown，人类可读、可直接编辑。PRD 由"已批准"状态的决策自动汇编生成；台账走不完，PRD 就不存在 v1——完整性门控由数据结构天然保证，不需要流程纪律。

2.2决策的生命周期：脑暴提出 → 追问挑刺 → 审批入档

环节 2（Brainstorming）
 ① 提出：主持人引导发散收敛，决策点被识别并登记入台账 （状态：讨论中）
 ② 初选：人做出初步选择，附理由 → （状态：已决待审）

环节 3（追问 · 挑刺）
 ┌─→ ③ 追问：质询者带着证据追问初选的依据、边界、未考虑的情形
 │   ④ 挑刺：从合规 / 风控 / 技术 / 体验四视角对抗性质疑这个选择
 └── ⑤ 人修订（回到③）或坚持（附辩护理由）
     ⑥ 审批：人显式确认 → 决策入档 （状态：已批准）

三条硬规则：

  1. 追问与挑刺必须带证据——尽可能引用知识简报中的监管条文 / 竞品事实 / 用户数据，无证据的质疑标注为"经验推测"
  2. 质询者与主持人角色隔离——质询者不读脑暴过程，只攻击决策结果，避免 AI 为自己引导出的方案辩护
  3. 审批是人的显式动作——AI 不得将任何决策自动置为"已批准"

2.3AI 四角色，对应四环节

角色环节职责行为约束
研究员1 知识文档全网收集监管 / 竞品 / 用户 / 技术信息，维护知识简报，为后续环节供给证据只收集、归类、引用，不下产品结论
主持人2 Brainstorming引导发散收敛，识别并登记决策点，呈现候选方案与权衡不替人决策，只提问和呈现
质询者3 挑刺 · 追问对每个初选决策追问 + 四视角对抗挑刺，驱动审批不读脑暴过程，只攻击决策结果
书记员4 PRD 汇编把已批准决策汇编成完整 PRD，维护台账与 PRD 的一致性只汇编、不创作；发现漂移时报告而非擅自修改

2.4证据链（Evidence Chain）

金融文档要经得起审计，本项目把这变成架构约束：台账中每个决策的证据引用一路可追溯到原始来源（URL + 抓取日期 + 原文摘录）。这同时治理金融场景最致命的风险——监管条文幻觉：每条引用可被人工抽查，抽查通过率是核心度量。

2.5文档生命周期管理

①失效检测

研究员发现新监管动态 / 竞品变化时，标记受影响的已批准决策为"已失效待重审"并说明原因——文档不会无声过期。

②一致性守护

任何对 PRD 的人工直接修改，书记员核对是否对应已批准决策，不对应则提示"先补决策，再改文档"。

③决策履历

每个决策的讨论、挑刺、改选过程全程留痕，半年后回看能知道"当初为什么这么定"。

SECTION 04

领域资产包（一等公民交付物）

工具废弃了这些资产也独立有价值，每期以"资产厚了多少"验收：

1金融产品决策清单 ★ 核心资产

金融产品从立项到上线必须做出的全部设计决策点，按域组织：适当性管理、合规路径与牌照、账户与资金流、风控规则、定价费率、数据合规、异常降级、运营客诉……每个决策点附追问提纲与常见候选方案。

2信源清单

监管 / 竞品 / 行业 / 用户四类信源，含更新频率与可信度分级。

3四视角挑刺量规

合规 / 风控 / 技术可行性 / 用户体验各自的质疑清单与严重度定级。

4金融 PRD 汇编模板

决策域 → PRD 章节的映射规则，含风险揭示、合规依据、资金流图等金融特有章节。

SECTION 05

分期路线图（每期回答一个研究问题）

一期W1–W5

环节 2 + 3 MVP（脑暴 → 挑刺审批）

先把系统心脏做出来：决策清单 v1（先覆盖 2–3 个决策域，如合规路径 + 资金流）+ 台账格式 + "脑暴提出 → 追问挑刺 → 审批"完整生命周期。

研究问题：决策生命周期相比"AI 直接生成 PRD"，决策质量是否可感知地更高？（挑刺改选率、决策辩护能力、单决策轮数与耗时）
验收实验：1 个真实/仿真金融需求，5–8 个决策点完整走生命周期，与"AI 一次性生成对应章节"对照。
二期W6–W9

环节 1 + 4（证据供给 → PRD 汇编）

接入知识文档环节为脑暴和挑刺供给证据；打通台账 → PRD 自动汇编，四环节首次成线。

研究问题：带证据的追问 vs 无证据追问，决策修改率和信任度差多少？汇编 PRD 在外部评审中表现如何？
验收实验：同批决策点两种追问各走一遍；汇编 PRD 交第三方 PM 盲评。
三期W10–W13

全线贯通 + 生命周期

补全决策清单到全部决策域；实现失效检测与回流。

研究问题：从知识收集到 PRD 端到端走完真实需求，总耗时与质量如何？失效检测能否拦住过期决策？
验收实验：1–2 个真实金融需求走全程；人为注入一条监管变化，观察失效检测表现。
SECTION 06

度量体系

度量定义验证什么
决策覆盖率决策清单中已批准（或显式暂缓）的比例完整性门控有效
挑刺改选率被挑刺后人改变选择的比例挑刺有效而非走过场（过低=没用，过高=追问质量差）
追问证据率 / 引用抽查通过率带证据追问占比；引用可验证比例证据链可信
决策辩护测试随机抽决策，PM 能否复述理由与放弃的备选决策真正被人做过
失效拦截率注入信息变化后被正确标记的决策比例生命周期管理有效
单决策平均耗时一个决策点从追问到批准的时长流程成本可接受
SECTION 07

范围边界（防膨胀条款）

明确不做：

  • 不做 PRD 之后的任何环节——原型、实施计划、工程链（TDD / 分支管理）全部不在范围内，项目收口在 PRD
  • 不做知识图谱、向量库、置信度评分等知识引擎（文档归档 + 检索起步）
  • 不做 skill 间自动编排（人显式进入每个环节）
  • 不做通用领域适配（只服务金融科技）
  • AI 不代写任何决策内容——这一条既是产品原则也是范围边界
任何新增能力须回答："它服务于决策台账的哪个状态流转？"答不上来即拒绝。
SECTION 08

风险与对策

风险对策
决策循环太重，PM 嫌烦不愿走完决策点分级：核心决策走全循环，次要决策允许"快速通道"（追问+批准，跳过挑刺）；以单决策耗时持续调参
挑刺流于形式或过度对抗以挑刺改选率校准量规；挑刺必须给出严重度和依据，不允许泛泛质疑
决策清单不全 = 系统性盲区清单按版本迭代，每次实验后复盘"漏掉了什么决策"；允许循环中动态新增决策点
监管信源抓取受限信源标注可达性，优先官方公开渠道，不可达项标注为人工补充
范围回潮、重蹈复杂度覆辙防膨胀条款 + 每期收尾复杂度审计（skill 数、状态数、调用关系数）
SECTION 09

9.2两种配置方案

A最小配置：1 人 + AI（可行底线）

B推荐配置：1 + 0.3 + 顾问（性价比最优）

负责人 0.5 FTE + skill 工程兼职（前两期每周 1–2 天）+ 合规顾问按次 + 外评池。总投入约 50–55 人天。多出的约 10 人天换来量规质量和实验可信度——研究结论能否立住的根基，全项目杠杆最高的投入。

成功标准

  1. 用决策循环把 1–2 个真实金融需求从知识收集走到 PRD，台账中每个决策有人做出、经过挑刺、显式批准、证据可抽查

  3. 沉淀可独立流通的金融产品决策清单 + 四视角挑刺量规 + 信源清单 + PRD 汇编模板 v1
